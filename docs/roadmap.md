# Twelve-week portfolio roadmap

Only Week 1 Day 1 is implemented. Every other item below is **planned** and may change as learning reveals gaps. Each week should conclude with a reviewable PR, tests, architecture notes, a small demonstration and reflection.

| Week | Focus | Planned evidence |
| --- | --- | --- |
| 1 | Node.js, HTTP, ESM, REST and testing | Day 1 task API implemented; later: edge cases, refactoring, HTTP semantics |
| 2 | TypeScript and developer tooling | Strict types, typed boundaries, linting and migration notes |
| 3 | SQL and persistence | Schema migrations, PostgreSQL repository and integration tests |
| 4 | Identity and API security | Authentication, authorization and threat model |
| 5 | React and browser fundamentals | Accessible task UI and component tests |
| 6 | Full-stack integration | API client, forms, loading/error states and end-to-end tests |
| 7 | Quality and accessibility | Contract tests, accessibility checks and regression strategy |
| 8 | Performance and caching | Measured profiling, pagination and justified optimizations |
| 9 | Background work and reliability | Queue experiment, retries and idempotency |
| 10 | Delivery and infrastructure | Containers, deployment pipeline and configuration management |
| 11 | Observability and operations | Structured logs, metrics, alerts and incident exercise |
| 12 | Capstone and portfolio review | Deployed demonstration, architecture review and retrospective |

Suggested weekly rhythm: Days 1–2 learn/build, Days 3–4 test and integrate, Day 5 document and review, Days 6–7 revisit gaps or rest. This is a learning guide, not a guarantee that every listed capability is complete.
